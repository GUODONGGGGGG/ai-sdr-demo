# AI SDR Agent DEMO

本项目是一套本地运行的中文 Web DEMO，覆盖 AQL 初筛、文字对话、企业候选、人工复核、意向判断和 AI SQL 输出。企业数据来自**本地模拟企业候选库，非真实工商数据**。评分和 SQL 就绪阈值均为演示规则，尚未用真实业务数据校准。

## 快速启动

需要 Python 3.10+。在本目录执行：

```bash
python3 -m pip install -r requirements.txt
python3 -m server.app
```

浏览器打开 <http://127.0.0.1:5050>。服务只监听本机；可用 `PORT=5051 python3 start_live.py` 启动当前演示端口。点击“运行当前预设脚本”仅适用于 A、B、C 的模拟模式；切换场景后先点击“创建 / 重置场景”。实时模式 A、B、C 由 DeepSeek 依据实际客户原话选择下一问，场景标题仅说明演示意图，不预设实时结果。D 为自由输入场景，仅支持实时模式，没有预设脚本或预填客户事实。实时模式的“本轮客户原话示例”来自同轮模型输出；点击只填入，不自动提交，也不会自动成为证据。刷新页面可恢复当前进程中的会话；重启服务后需重建。

## 两种运行模式

- **预设样例模拟运行**：无需 Key。固定样例规则处理回复；运行记录标明 `simulated`，不冒充实时 AI。自由输入只能识别有限的演示措辞，未识别内容保持未知。
- **DeepSeek 实时推理**：先在服务端环境设置 `DEEPSEEK_API_KEY`，再启动服务。可选 `DEEPSEEK_MODEL`，默认 `deepseek-flash`。页面只显示 Key 是否已配置，绝不显示值。三个 Agent 分别调用模型；每次结构化输出失败最多重试一次，再失败进入 `REVIEW`，保留错误，绝不回退到预设样例。

实时模式先做对话与字段提取，再并行执行抬头确认Agent和意向判断Agent，减少串行等待；没有增加示例生成的额外请求。页面在请求期间显示“分析中…”。实际耗时仍取决于模型和网络。

## 腾讯云托管保持可访问

本项目容器监听 80 端口，`/healthz` 用于健康检查。代码本身无法决定腾讯云在空闲时是否保留实例。若分享链接需要随时打开，请在云托管控制台将当前服务的运行模式设为自动扩缩容且**最小实例数为 1**（或选持续运行并保留 1 个实例），并确认该版本有 100% 流量、环境未冻结、已开启超限按量服务且账户未欠费。最小实例为 1 会持续产生实例费用；最小实例为 0 可节省空闲费用，但再次访问可能经历冷启动。设置后从其他浏览器访问公网地址及 `/healthz` 验证；若仍需手动重启，检查云托管运行日志和服务状态，以区分实例崩溃、环境冻结和计费停服。

实时模式对客户原话中的门店数、设计师人数再做明确数值核对；模型漏掉时可从原话补全。客户明确说出“想把……统一”等需求而模型漏抽时，也用该原话子句补全需求字段。前一轮有证据的字段在后一轮保留。这是服务端规则补全，不是预设答案。

商机判断要求意向证据能在客户原话中逐字核对。若模型引文不准确，但客户明确说出了预算、上线计划等信号，页面会标注“客户原话规则补证”，并展示该原话。购买意向与同意销售联系分别核验；有意向但未同意联系时保持 REVIEW，只补问联系意愿，交接步骤显示“待补充”。

文字外呼以智能助理身份开场，之后由模型在未问过的目标中选择具体下一问，覆盖需求、现状、痛点、目标、规模、试点、时间、预算范围、决策参与人与联系同意。服务端检查问题是否单一、是否重复、是否对应目标，以及示例是否夹带未询问的公司或规模信息。每通电话最多接收 10 轮客户回复；约 6–9 轮已有充分信息时可礼貌收尾，客户拒绝或表示忙碌时提前停止。已具备 SQL 交接条件时继续补问有价值信息，只有通话结束后才输出 READY 和 AI SQL。客户记不清企业全称时不重复追问，转内部人工核对。电话中不索取营业执照、照片、统一社会信用代码、证件或上传资料；违规建议会被规则话术替换并明确标注非模型输出。

macOS/Linux 的环境变量示例：

```bash
export DEEPSEEK_API_KEY='在本机终端设置，不写入项目文件'
export DEEPSEEK_MODEL='deepseek-flash'
python3 -m server.app
```

不想输入较长的环境变量命令时，可直接运行 `python3 start_live.py`，按提示粘贴 Key。输入不会在终端显示；Key 只保存在当前进程内存，不写入项目文件。保持该终端窗口打开，页面访问 <http://127.0.0.1:5050>。

不要把真实 Key 粘贴到聊天、前端或录屏中。实时测试只用虚构客户和企业信息。`.env.example` 只列变量名，应用本身不读取 `.env` 文件。

## 四条演示路线

1. A：选“正常生成 AI SQL”，运行五轮预设脚本。智能助理依次问公司称呼、需求、门店与设计师规模、近期计划、销售联系意愿；客户逐轮回答。结果为 `READY`，六个字段均有来源与证据。
2. B：选“抬头歧义与人工复核”，重置并运行五轮预设脚本。客户记不清公司完整名称时不追索证照；两个候选同时出现，电话礼貌收尾后状态 `REVIEW`，没有 SQL。内部人工确认其中一个候选后，若已有客户需求和联系同意，才转为 `READY`；设计师人数仍显示未知。
3. C：选“低意向”，重置并运行。结果为 `NURTURE`，没有 SQL，停止追问。
4. D：选“自由输入”，切换到 DeepSeek 实时推理，创建新线索后自行输入任意客户原话。系统不提供预设回复，下一问和最终状态由实际原话及模型输出决定。若本地模拟企业库没有该公司，客户明确自报完整法定名称仍可确认抬头，行业保持未知；简称须人工复核。

人工复核还可手动修正企业全称、退回补问；操作和时间留在记录区。企业抬头未确认、无匹配、拒绝联系等情况均不会生成销售可跟进 SQL。

## 验证

```bash
python3 -m unittest discover -s tests -v
python3 demo.py A
python3 demo.py B
python3 demo.py C
```

`demo.py` 是第一阶段保留的命令行查看器。自动化测试覆盖规则路径、人工复核、无 Key、无效 JSON 重试、模型选择追问目标、自由输入与三 Agent 实时链路，共 31 项通过。新版真实 API 联调记录在 `docs/live-verification-framework.json`、`docs/live-verification-b-framework.json`、`docs/live-verification-c.json` 和 `docs/live-verification-d.json`；所有客户与企业均为虚构，不代表真实业务准确率。

- `docs/product-design.md`：产品设计文档，可改名加入姓名后提交。

- `docs/screenshots/`：已验证的关键路径截图。
